July 3 — Critical Fix

Inventory
Pieces & Carats Desync

The core inventory ledger could show incorrect totals. Here's what happened and how it was fixed.

🐛
The Problem
Editing a catalog spec's weight would retroactively recalculate past movements. The Quick Stock Adjustment feature allowed arbitrary edits that bypassed validation.
Data Integrity
✅
The Fix
Every movement now snapshots the avg-weight at creation time. 0 pcs → 0 ct → $0 is enforced. Quick Stock Adjustment was removed entirely.
Snapshot Math
🔒
New Safeguards
Replaced with a manager-only Inventory Correction that creates a full audit trail. Added a reconciliation script + UI modal for bulk repair.
Manager-Only
🧹
Cleanup
Removed a hardcoded one-time migration script from App.tsx that was injecting bulk return data for project 1351. Restricted /projects route to Manager & Designer only.
Tech Debt
July 7 & 10 — Security

Firebase
Security Rules Fixed

Two permission issues were silently blocking users from core workflows.

🔤
Manager Role Mismatch
Firestore rules checked for 'MANAGER' but user documents stored 'Manager'. Case-sensitive comparison meant managers were denied write access.
1-Line Fix
📸
Evidence Upload Blocked
Setters and designers couldn't upload evidence photos — both Firestore and Storage rules restricted writes to Manager-only. Now any authenticated user can attach evidence.
Permissions

Each repair gets a code in the format REP-240723-DIAMOND — combining date and repair type. Five categories: Diamond Setting, Ring Resizing, Broken/Solder, Watch Repair, General.

July 23 — Auth & Profiles

Self-Healing
Profile System

Legacy profiles, missing photos, and invisible project assignments — all resolved.

🧬
Legacy Profile Merging
Users with pre-Auth orphan documents had multiple Firestore profiles (one with their photo, another with their role, a third from a rename). On login the store now scans all user documents and matches by email, authUid, legacy ID arrays, and name similarity — then merges them into one authoritative profile.
Self-Healing
👁️
Designer Dashboard — Invisible Projects
Designers couldn't see projects assigned to them because acceptedProfileIds only checked the current ID and legacy IDs — not authUid, name, or email. The match set now covers all identity signals, including looking up the assigned user's document to cross-match by name.
Matching
📷
Profile Photo Resolution
getUser(id) now checks profilePhoto, photo, profileImage, avatar fields across linked profiles. Falls back to matching by legacy IDs, same name, or email prefix (e.g., harout from harout@kilani.com).
Photo Fallback
🔗
Setter Repair Callback
After creating a quick repair, the setter wasn't redirected to the new project. The QuickRepairModal was missing the currentUser prop and onProjectCreated callback. Now wired end-to-end.
